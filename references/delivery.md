# 导出与验收

## 进入导出阶段

先按 planning.md 判断是否已进入详细规划：核心方向和会改变路线的关键安排已由用户表达、选定或明确交由你决定，或用户明确要求导出当前草案/已有计划。只有出发地、日期、人数和预算时，不能因为模板可以填写就自动生成 HTML。交付条件性草案用于表达未落实的外部条件或用户要求的假设方案，不能替代对核心偏好的了解。

## 命令

Python 3 标准库即可。从任意目录调用 Skill 的 scripts/travel_plan.py；输入输出路径显式给出。`init` 创建完整字段骨架；也可参考 assets/demo-plan.json（所有地名、规则和订单都是模拟，不可用于出行）。

```text
python <skill>/scripts/travel_plan.py check plan.json --as-of YYYY-MM-DD
python <skill>/scripts/travel_plan.py render plan.json --out travel-plan.html --as-of YYYY-MM-DD
python <skill>/scripts/travel_plan.py audit travel-plan.html
```

check 输出 JSON：schema_errors、blockers、warnings、effective_status、budget。退出码 2 表示结构错误，1 表示可行性阻断，0 表示已实现的检查未发现阻断。render 遇结构错误不写文件；可行性阻断会写醒目“条件性方案”及问题清单并返回 1，不能因生成文件就说可出发。输出已有文件时默认拒绝，另用新文件名；显式 `--force` 才覆盖。

audit 检查静态资源/API/CSS 依赖和本地资源引用（只允许自包含资源与显式在线链接），不证明浏览器兼容。链接联网属于增强能力，不算核心依赖。未知模板改动后不能仅凭 audit 通过就交付。

## 内容验收

默认导出旅行手帐版式：奶油色纸张、陶土橙标签、行程时间线与可勾选清单。封面为杂志刊头式纯排版：细线夹一行刊头小字（日期 · 人数 · 预算），大标题与出发地→目的地，底部细线后分三栏大数字（行程天数 / 预算速览 / 出发清单进度）。日程在清单前，偏好与勾选说明可折叠；重要阻断项和订单状态保持直接可见。来源引用以上标编号指向"随身资料夹"，查证记录默认折叠分层展示，来源冲突保持直接可见。不使用装饰插画；不依赖在线字体、图片或其他资源。全程同一 UTC 偏移的行程（如国内游）省略 UTC 标注；出现多个偏移（跨时区）时短时刻旁保留日期及 UTC 偏移，跨午夜时展示两端完整日期和偏移，避免只看时钟误读。

人工复核来源、地址真实性、时间窗口含义、行李、首尾天、用餐/休息、强度、已知订单和风险备选。脚本只检查显式输入条件，不推断未记录的营业日或隐含需求。constraints.status 的 satisfied 必须有 evidence；语义正确性仍由规划者负责。

参考 budget 范围要与用户硬约束一致。所有关键 unresolved、booking、source 冲突应可见；探索方案允许未知，不能伪装 ready。

## 浏览器离线测试

### 待办勾选

HTML 的待办支持点击标题、复选框或键盘空格切换，初始值来自 tasks.status。勾选进度仅保存在当前浏览器的 localStorage，不回写 plan.json，也不改变订单确认记录和生成时的核验结论。内容版本由 plan.json 除 generated_at 外的全部内容生成指纹，再按待办 ID 分别保存；仅重新导出或改变生成时间不重置进度，内容或 revision 改变则采用新版初始值。

保存成功时说明保存范围；浏览器拒绝读写时降级为当前页面内勾选并提示无法保存。禁用脚本时复选框不可操作，仍展示生成时状态和全部事项。换浏览器、换设备、清理浏览器数据或改变本地文件打开方式后可能无法恢复，不承诺跨设备同步。

验证初始 pending/done、标题点击、键盘切换、勾选与取消后的重载恢复、不同内容版本隔离；模拟存储读取和写入拒绝，确认页面可继续勾选且显示降级提示。检查顶部核验结论、订单摘要不随勾选改变。

优先用环境已有且授权的浏览器自动化工具。当前端工具不可用时只报告静态检查，不声称做过动态离线检查。

1. 用 `file://` 打开生成文件。在独立的测试页面/上下文阻断网络请求或设为 offline，再重新加载，记录实际方法。不要改变用户日常浏览器全局网络设置。
2. 查看手机尺寸（例如 390×844、窄屏 320px）有无横向溢出、文字遮挡，检查不同日期的跳转、问题清单、预算及来源完整显示。
3. 点击复制；API 拒绝时应显示“长按或选择地址复制”，地址仍可选中，不能误报已复制。
4. 在禁用脚本的独立测试上下文重开文件，确认全部日期、地址、预约和预算可读。无法禁用时明确此项未实测；模板按静态 HTML 生成，不能靠 JS 注入核心内容。
5. 检查浏览器控制台错误和网络尝试，保留简短结果及必要截图。真实手机保存/打开流程未测试则单独标记，不以桌面模拟冒充。

## 打开与分享

告诉用户保存 HTML 后用支持本地网页的浏览器/查看器打开；聊天应用预览器的脚本支持不可假定。首次使用请在实际手机离线打开确认。若目标设备无法顺利打开，按已有工具能力导出静态 PDF，不能仅改扩展名；PDF 也需要检查。模板自带打印排版，浏览器可另存 PDF。

分享版只保留必要集合、路线、餐饮和注意事项；导出前删掉不必要的订单身份和联系方式。默认脚本不自动生成分享版或发布链接。

不要为基础交付引入 PWA、Service Worker、账号或后台。它们只有在用户确有需求且验证环境支持时才属于新增范围。
